## 二、零基础怎么开始？（心态 + 方法）

### ❌ 错误做法
- 一上来刷 Hard 题 → 受挫放弃。
- 只看题解不自己写 → 永远学不会。
- 追求刷题数量 → 不总结，同类题换个马甲又不会。
- 抄代码 → 肌肉记忆建立不起来。

### ✅ 正确做法 🔴
1. **先学数据结构基础**（数组/链表/树/栈/队列/哈希）—— 这是地基。
2. **按专题刷**（不要随机刷）—— 同类题集中突破，形成肌肉记忆。
3. **先易后难**：Easy → Medium → Hard，70% Medium 为主。
4. **每题限时**：Easy 15min，Medium 30min，超时看题解。
5. **看题解后必须重写一遍**（关闭答案默写）。
6. **总结模板**：每类题有固定套路（双指针、滑动窗口、回溯模板）。
7. **间隔重复**：3 天后、7 天后、15 天后复习错题。
8. **面试前 1 个月**：模拟限时写，白板练手。

## 六、LeetCode 解题流程模板（养成习惯）

拿到题按这个流程，不要上来就写代码：

```
1. 读题（2min）：明确输入、输出、约束、边界（空数组？负数？重复？）
2. 想思路（5-10min）：
   - 暴力法是什么？（保底）
   - 能否优化？用什么数据结构/算法？
   - 画图模拟几个例子
3. 写代码（10-15min）：
   - 先写主框架，再填细节
   - 注意边界处理
4. 手动测试（3min）：用例子跑一遍，检查边界。
5. 分析复杂度：时间 O(?)、空间 O(?)，说出来。
6. 优化/总结：有没有更好解法？记录套路。
```

**面试时**：一定要**边想边说**（Think Aloud），把思路讲给面试官听，不要闷头写。

## 七、复杂度分析速查（必须会）

### 大 O 表示法
衡量算法随输入规模 n 增长的效率，**忽略常数和低阶**。

```
从快到慢：
O(1)       常数     数组下标访问
O(log n)   对数     二分查找
O(n)       线性     遍历
O(n log n) 线性对数  排序（快排/归并）
O(n²)      平方     双重循环、冒泡
O(2ⁿ)      指数     暴力递归（斐波那契）
O(n!)      阶乘     全排列
```

**面试经验**：n ≤ 10 → O(n!)；n ≤ 20 → O(2ⁿ)；n ≤ 100 → O(n³)；n ≤ 1000 → O(n²)；n ≤ 10⁵ → O(n log n)；n ≤ 10⁶ → O(n)；n > 10⁶ → O(log n) 或 O(1)。

### 空间复杂度
额外用多少内存。递归要算调用栈深度。

## 九、常见易错点（Java 专项）

🔴 **int 溢出**：`int mid = (left + right) / 2` 可能溢出，用 `left + (right - left) / 2`。
🔴 **负数取模**：`-7 % 3 = -1`（Java），不是 2。要正余数用 `(a % b + b) % b`。
🔴 **数组越界**：注意 `i < n` 还是 `i <= n`，空数组判断。
🔴 **== 比较对象**：`Integer a = 127, b = 127` 相等（缓存），`128` 不等。比较用 `.equals()`。
🔴 **String 不可变**：`s += "x"` 每次新建对象，循环拼接用 `StringBuilder`。
🔴 **集合遍历删元素**：`for-each` 删 ConcurrentModificationException，用迭代器或 `removeIf`。
🔴 **二维数组行列**：`int[][] grid`，`grid.length` 是行数，`grid[0].length` 是列数。

## 十、面试现场 Tips

1. **先 clarify**：问清输入范围、边界、是否唯一解。
2. **先说思路再写**：Think Aloud，让面试官知道你在干嘛。
3. **先暴力再优化**：有保底方案比卡死强。
4. **写完手动跑测试用例**：体现严谨。
5. **说出复杂度**：时间 + 空间。
6. **不会别硬撑**：说出你知道的相关知识，面试官会引导。
7. **白板练手**：没有代码补全/调试，提前适应。
