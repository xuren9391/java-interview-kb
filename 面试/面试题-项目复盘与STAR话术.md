# 面试题 - 项目复盘与 STAR 话术（★最重要）

> ⚠️ **这是整个面试准备中最重要的文档**。
> 技术题答得好只是"不掉分"，**项目讲得好才是"加分项"**。资深岗面试 60% 时间在聊项目。
> 决定你能不能拿到 offer 的，不是背了多少八股，而是**能不能把自己的项目讲出深度和亮点**。

---

## 一、为什么项目复盘最重要？

面试官的逻辑：
1. 简历上写的项目 → 你说"做了 X" → 面试官要验证你**真的做了、真的懂、真的有思考**。
2. 通过不断追问（5Why）一层层深入：
   - 第 1 层：你做了什么？（表面）
   - 第 2 层：为什么这么做？（取舍）
   - 第 3 层：有没有其他方案？为什么不用？（视野）
   - 第 4 层：遇到什么问题？怎么解决的？（深度）
   - 第 5 层：量化的结果是什么？（价值）
   - 第 6 层：如果重来你会怎么改？（反思）

**讲不清的后果**：面试官怀疑你"只是参与、没主导、没思考"，直接降级评价。

---

## 二、STAR 法则（项目话术的骨架）

每个项目按 STAR 讲：

```
S (Situation) 背景：
  - 业务场景、团队规模、你的角色
  - 面临什么问题/挑战（有数据更好）

T (Task) 任务：
  - 你的目标是什么
  - 有什么约束（时间、资源、技术）

A (Action) 行动：  ← 重点，占 60% 篇幅
  - 你做了什么决策
  - 为什么这么选（取舍）
  - 具体技术方案
  - 遇到的难点 + 解决过程
  - 你的具体贡献（"我"而不是"我们"）

R (Result) 结果：
  - 量化收益（数字！性能提升 X%、成本降 Y%、QPS 从 A 到 B）
  - 业务价值
  - 复盘反思（如果重来做哪些改进）
```

**关键原则**：
- **用"我"不用"我们"**（区分你的贡献）。
- **量化**（RT 从 2s→200ms，QPS 1k→5k，成本降 30%）。
- **讲取舍**（为什么 A 不选 B）。
- **讲反思**（踩坑、改进）。
- **控制在 3-5 分钟**，留时间给追问。

## 三、项目深度自查表（每个项目过一遍）

针对简历上**每个项目**，确保能答出以下（面试官会随机挑一个深挖）：

### 1. 整体
- [ ] 一句话讲清这个项目做什么、解决什么业务问题。
- [ ] 画得出来系统整体架构图（白板）。
- [ ] 你在这个项目里的**具体角色**（主导/核心/参与）。
- [ ] 团队多少人、你怎么分工协作。

### 2. 技术决策（深度追问区）
- [ ] 为什么用这个技术/方案？（不用替代方案的原因）
- [ ] 核心技术难点是什么？怎么解决的？
- [ ] 数据流怎么走的？（一次请求的完整链路）
- [ ] 数据量、QPS、并发量是多少？
- [ ] 数据库表设计、分片策略。
- [ ] 缓存策略、缓存一致性怎么保证。
- [ ] 用了什么中间件，为什么选它。

### 3. 难点与亮点（闪光点）
- [ ] **最有挑战的一个技术问题**是什么？怎么排查、怎么解决？
- [ ] 你做的**最有成就感的优化**是什么？前后对比数据。
- [ ] 有没有**架构演进**（从 v1 到 v2 为什么改）？
- [ ] 踩过什么**坑**？怎么补救的？事后怎么预防？

### 4. 稳定性
- [ ] 怎么保证高可用（监控、告警、预案）？
- [ ] 出过什么**线上故障**？怎么处理的？
- [ ] 压测过吗？瓶颈在哪？怎么优化的？

### 5. 量化结果
- [ ] 性能提升（RT、QPS、吞吐）。
- [ ] 成本降低（机器、费用）。
- [ ] 业务价值（覆盖范围、效率、收入）。
- [ ] 技术沉淀（专利、开源、内部推广）。

### 6. 反思
- [ ] 现在回头看不满意的地方？
- [ ] 如果重做会怎么改？
- [ ] 这个项目让你学到什么？

> 💡 **建议**：把每个项目的答案**写下来**（不是想），白纸黑字过一遍，你会发现很多讲不清楚的地方。

## 四、项目话术模板（照着填）

### 模板 A：性能优化类项目

> **S 背景**：XX 系统（订单/商品/支付...）在大促时接口 RT 从 200ms 飙升到 2s，P99 超 5s，用户投诉率上升 30%，影响转化。
>
> **T 任务**：我是核心开发，负责排查并优化，目标 RT 降回 200ms 以内、扛住 5 倍峰值。
>
> **A 行动**：
> 1. **定位**：用 SkyWalking 链路追踪发现瓶颈在 DB（慢查询）+ 缓存命中率低（40%）。
> 2. **DB 优化**：explain 发现没走索引 → 加联合索引（覆盖）→ 慢查询从 1s→10ms。
> 3. **缓存重构**：原本单级 Redis 命中率低 → 改**多级缓存**（本地 Caffeine + Redis），热点预加载，命中率提到 90%。
> 4. **异步化**：非核心链路（通知、统计）改 MQ 异步，主链路 RT 降一半。
> 5. **JVM 调优**：FullGC 频繁 → 换 G1 + 调 NewRatio，停顿降 80%。
>
> **R 结果**：RT 从 2s 降到 150ms（P99 <500ms），QPS 从 2k 提到 1w，大促 0 故障，获团队季度奖。
>
> **反思**：缓存击穿当时没做好（热点 key 失效打 DB），后来加了互斥锁 + 永不过期方案。

---

### 模板 B：架构演进类项目

> **S 背景**：原单体系统，业务膨胀代码耦合，迭代冲突频繁，单库千万级数据性能下降。
>
> **T 任务**：主导微服务化改造 + 分库分表。
>
> **A 行动**：
> 1. **领域建模**：用 DDD 事件风暴梳理限界上下文，拆分订单/商品/库存/用户 4 个服务。
> 2. **数据拆分**：按业务垂直分库 + 按 userId 水平分表（ShardingSphere），单表降到百万级。
> 3. **服务治理**：Nacos 注册配置 + Sentinel 熔断限流 + Gateway 网关 + SkyWalking 链路。
> 4. **一致性**：跨服务用本地消息表 + MQ，对账兜底。
> 5. **灰度迁移**：双写双读 + 数据校验 + 平滑切流，0 故障迁移。
>
> **R 结果**：迭代效率提升（团队并行）、单库性能恢复（QPS 5x）、系统可扩展性大增。
>
> **反思**：拆得太细了，有些边界划得不准导致跨服务调用多，后期合并了几个。

---

### 模板 C：从 0 到 1 类项目

> **S 背景**：业务有 XX 新需求，无现成方案。
>
> **T 任务**：从 0 设计并落地。
>
> **A 行动**：需求分析 → 技术选型（对比 3 方案）→ 架构设计 → 核心开发 → 联调上线。
>
> **R 结果**：按时上线，支撑 XX 业务，沉淀为通用组件，被 N 个团队复用。

## 五、高频追问应对（提前想好）

### "你在这个项目里最大的挑战是什么？"
- 准备 1 个**技术硬骨头**（排查线上疑难 / 架构两难 / 性能瓶颈攻坚）。
- 讲过程：现象 → 假设 → 验证 → 根因 → 方案 → 结果。

### "为什么用 A 不用 B？"
- 准备 2-3 个**有取舍的技术决策**（MQ 选型、分库分表策略、缓存方案）。
- 讲对比维度：性能、成本、团队能力、成熟度、风险。

### "出过线上事故吗？怎么处理的？"
- **诚实**讲一个（别装没出过，没人信）。
- 重点讲**处理过程 + 复盘改进**（止血 → 根因 → 预防），体现责任心和成长。
- 别讲低级错误（如删库），讲复杂场景下的判断失误。

### "如果重做你会怎么改？"
- 体现反思能力。讲 1-2 个具体改进点（不要全盘否定，讲"如果当时有 X 条件会做 Y"）。

### "你和别人意见冲突怎么办？"
- 讲事实数据、做 POC 对比、邀请资深人评审、最终对事不对人。
- 体现协作 + 判断力。

## 六、项目优先级建议

简历准备 **3-5 个项目**，按重要度分：

1. **旗舰项目（1 个）**：最复杂、最有亮点、你主导的。准备到能讲 20 分钟 + 应对所有追问。
2. **核心项目（2 个）**：能体现你不同能力的（一个偏架构、一个偏性能优化 / 分布式）。
3. **辅助项目（1-2 个）**：体现广度（AI、新技术、跨团队协作）。

**面试时根据岗位选讲**：
- 冲架构师 → 讲架构演进项目。
- 冲性能/高并发 → 讲优化项目。
- 简历有 AI → 讲 AI 项目。

---

## 七、练习方法（强烈推荐）

1. **写下来**：每个项目按 STAR 写成文档（500-1000 字），存到本地。
2. **录音回听**：对着手机录一遍，回听找问题（卡顿、啰嗦、没重点）。
3. **找人对练**：让朋友/同事扮面试官追问，练临场反应。
4. **迭代**：每次真实面试后，把被问住的地方补回文档。

**目标**：每个项目讲得像讲故事，自然流畅，3 分钟讲完核心，能应对 15 分钟追问。

---

## 八、避坑清单

❌ **别用"我们"**（掩盖你的贡献）→ ✅ 用"我主导/我负责/我设计了"。
❌ **别只讲做了什么不讲为什么** → ✅ 每个决策讲取舍。
❌ **别堆技术名词** → ✅ 讲清解决什么问题。
❌ **别夸大数据**（被追问露馅）→ ✅ 实事求是。
❌ **别贬低前公司/同事** → ✅ 客观讲事实。
❌ **别说"这是团队做的我不清楚"** → ✅ 讲你清楚的部分，不清楚的诚实说。
❌ **别超时**（一个项目讲 10 分钟还没完）→ ✅ 3-5 分钟讲核心，留追问空间。

## 九、给你的作业（按这个填）

为你的**旗舰项目**，按下面格式填一份（填完才算准备好）：

```
项目名：
业务背景（S）：
我的角色与任务（T）：
核心行动（A）——至少 3 个技术决策 + 1 个难点解决：
  决策1：做了什么 + 为什么这么做 + 替代方案及代价
  决策2：...
  决策3：...
  难点：现象 → 排查 → 根因 → 方案 → 结果
量化结果（R）：
反思（如果重做怎么改）：
可能被追问的 5 个问题及答案：
  1.
  2.
  3.
  4.
  5.
```

**至少准备 3 个项目**这样填。这是面试前必做的功课，比刷 100 道八股更值。

---

> 🎯 **一句话总结**：面试官招的是"能扛事、能拍板、有思考"的人，不是"背得多"的人。把你的项目讲成一个个有挑战、有决策、有结果的故事，你就赢了 80%。
