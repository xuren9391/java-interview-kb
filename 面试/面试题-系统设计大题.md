## 答题框架（7 步法，先记牢再做题）

```
Step 1 澄清需求（3-5min）：核心功能？量级？读写比？一致性？延迟？
Step 2 估算容量（3-5min）：QPS、存储、带宽、机器数
Step 3 高层设计（5-10min）：画核心组件框图，说明数据流
Step 4 详细设计（15-20min）：数据模型、接口、核心算法、按面试官兴趣深入
Step 5 扩展性（5-10min）：缓存、MQ、分库分表、CDN
Step 6 可靠性（5min）：单点、容灾、限流熔断、监控
Step 7 总结权衡：复述方案，讲取舍和替代方案代价
```

**口诀**：问清楚 → 估容量 → 画框架 → 深入核心 → 扩展容灾 → 讲权衡

## 题 1 🔴🔴 短链系统（经典入门）

**澄清**：长→短生成、短→长跳转。日新增 1 亿，读 QPS 10w。

**估算**：5 年存储 ≈ 1亿×365×5 = 1825 亿条，每条 500B → ≈ 90TB（分库分表）。

**高层**：发号器 → 生成短码 → 存(短码→长链) → 返回；访问 → 查缓存 → 302 跳转。

**核心 - 短码生成**：
- 发号器（自增 ID → 62 进制）。6 位 = 62^6 ≈ 568 亿，够用。
- 替代：MD5 取前 6 位（可能冲突需查重）。

**301 vs 302**：301 永久（浏览器缓存，省服务器但统计不到）；302 临时（每次访问短链服务，能统计）。业务要统计用 302。

**扩展**：热点短链 Redis 缓存，命中率 90%+。

核心：Redis Lua 预扣（拦 99%）+ MQ 异步下单 + DB 乐观锁兜底（WHERE num>0）+ 防刷（限流/验证码）。

## 题 3 🔴 Feed 流（朋友圈/微博）

**三种模式**：
| 模式 | 写 | 读 | 适用 |
|------|----|----|------|
| 拉（Pull） | 不推，读时实时拉 | 慢 | 写少读少 |
| 推（Push/扇出写） | 发帖推到所有粉丝收件箱 | 快 | 粉丝适中 |
| 推拉结合 | 普通人推，大 V 不推粉丝拉 | 中 | 微博典型 |

**收件箱**：Redis ZSet，score=时间戳，member=postId，ZREVRANGE 分页。

**避免大 V 热点**：大 V 帖子独立存，粉丝读时拉取合并。

---

## 题 4 🔴 排行榜

- Redis ZSet：`ZADD/ZREVRANGEBYSCORE`，单机十万级成员。
- 分桶 ZSet：超大规模按维度（地区榜、全国榜）。
- 实时：用户行为异步累加 → Redis。

## 题 5 🔴 IM / 消息推送

**核心难点**：消息可达性、长连接、多端同步。

**架构**：客户端 ← WebSocket/长连接网关 ← 消息路由 ← 存储 + 推送。

**消息可达性**：
- **客户端 ACK**：服务端发 → 客户端 ACK → 删离线。
- **消息 ID + 序号**：去重、排序。
- **离线消息表**：未 ACK 的存，上线拉取。
- **QoS**（参考 MQTT）：0 至多一次、1 至少一次、2 恰好一次。

**多端同步**：每会话自增 sequence，客户端上报 last_seq，服务端返回 > last_seq 的消息。

**长连接**：Netty/自研网关，单机维持几十万连接（epoll + 内存优化）。

## 题 6 🔴 延迟任务平台

| 方案 | 优 | 劣 |
|------|----|----|
| DB 轮询 | 简单 | 慢、压 DB |
| Redis ZSet | 简单 | 需扫描、重启丢 |
| 时间轮 | 高效 | 单机、重启丢 |
| RocketMQ 延时 | 可靠 | 等级固定 |
| 自建多级时间轮+持久化 | 灵活 | 复杂 |

生产：RocketMQ 延时 / Redis ZSet + 持久化兜底。

## 题 7 🔴 抢红包

类似秒杀 + 随机金额算法（二倍均值法保证公平）：
```
每次抢：金额 = random(0.01, 剩余总额/剩余人数 × 2)
最后一个：剩余全部
```
Redis 预扣（原子扣份额）+ MQ 异步落库 + 防刷。

## 题 8 🔴 12306 余票

**核心难点**：余票扣减防超卖 + 海量查询。

- **查询**：走缓存/ES，余票预聚合。
- **购票**：库存表分库分表（按车次），Redis 预扣 + DB 行锁兜底。
- **难点**：区间票（A→B→C，买 A→B 影响 B→C）——按区间建模余票。

## 加分技巧（很重要）

1. **先问需求**：不问就画 = 减分。问"用户量级、读写比、一致性、延迟"。
2. **先估算**：体现"规模感知"。
3. **画图清晰**：客户端→网关→服务→存储分层。
4. **讲取舍**：每个选择讲为什么 + 放弃方案的代价。
5. **主动暴露瓶颈**：识别单点/热点，主动说解决。
6. **结合实际**："我们 XX 场景踩过坑，所以这里用 XX"。
7. **不会就说思路**：别装懂。
8. **时间管理**：按 7 步节奏，别陷细节。
